SMT verification notes for ML-KEM polynomial reduction

In post-quantum schemes like ML-KEM (Kyber), side-channel attacks like KyberSlash don't attack the lattice math—they target small timing discrepancies during modular reduction and Number Theoretic Transform (NTT) butterfly loops.

In PQCanary, we use the Z3 SMT solver to statically check polynomial arithmetic for out-of-bounds values and secret-dependent branches.

1. Checking Layer by Layer

Polynomial operations in ML-KEM work over $R_q = \mathbb{Z}_q[X]/(X^{256} + 1)$ with $q = 3329$.

Trying to verify an entire 256-point NTT in an SMT solver all at once blows up into too many bitvector clauses and times out. Instead, we verify inductively: checking each butterfly step and modular reduction separately to confirm that coefficients stay strictly within $[-q/2, q/2]$.

2. Symbolic Range Check in Z3

Here is a simplified example checking Montgomery reduction bounds in Rust with Z3:

use z3::ast::{Ast, BV};
use z3::{Config, Context, SatResult, Solver};

pub fn check_montgomery_bounds() -> Result<(), String> {
    let cfg = Config::new();
    let ctx = Context::new(&cfg);
    let solver = Solver::new(&ctx);

    let q = BV::from_i64(&ctx, 3329, 32);
    let half_q = BV::from_i64(&ctx, 1664, 32);
    let neg_half_q = BV::from_i64(&ctx, -1664, 32);

    // Symbolic intermediate multiplication result
    let input = BV::new_const(&ctx, "prod", 32);

    // Constant-time Montgomery reduction: (a - ((a * QINV) & 0xFFFF) * q) >> 16
    let qinv = BV::from_i64(&ctx, -3327, 32);
    let mask = BV::from_i64(&ctx, 0xFFFF, 32);
    let t = input.bvmul(&qinv).bvand(&mask);
    let reduced = input.bvsub(&t.bvmul(&q)).bvashr(&BV::from_i64(&ctx, 16, 32));

    // Desired range: -q/2 <= reduced <= q/2
    let in_bounds = reduced.bvsge(&neg_half_q)._and(&[&reduced.bvsle(&half_q)]);

    // Check if any input violates the bound (negation is SAT)
    solver.assert(&in_bounds.not());
    match solver.check() {
        SatResult::Unsat => Ok(()), // Proved: No input violates modular bounds
        SatResult::Sat => Err("Bound violation found".into()),
        SatResult::Unknown => Err("Solver timeout".into()),
    }
}

3. Memory & Branch Invariants

We also check that memory load addresses during NTT passes do not depend on secret polynomial values:

  • Verify that conditional branches (br i1) never evaluate on secret-tainted variables.
  • Assert that load offsets satisfy $\frac{\partial \text{offset}}{\partial \text{secret}} = 0$.

This statically catches subtle timing leaks before running empirical side-channel tests.

Deobfuscating Quantum Intermediate Representation (QIR)

QIR compiles quantum circuits into LLVM IR by emitting quantum gates as external calls (like @__quantum__qis__h__body or @__quantum__qis__cnot__body).

During compilation and transpilation, circuits often end up with redundant gates, reordered operations, or continuous rotation gadgets that make the circuit hard to inspect.

In QIR Reversing, we parse the bitcode, clean up the circuit using basic quantum commutation rules, and check that the resulting circuit has the exact same unitary behavior.

1. Commutation Rules

If two gates commute ($[A, B] = AB - BA = 0$), they can swap order along qubit wires without changing the circuit's action:

  • Disjoint wires: Gates on separate qubits always commute: $[A \otimes I, I \otimes B] = 0$.
  • Phase gates: Diagonal gates in the computational basis commute: $[Z, S] = [S, T] = [R_z(\alpha), R_z(\beta)] = 0$.
  • Controlled gates: $CX$ commutes with $Z$ on control and $X$ on target.

Sliding commuting gates together lets us cancel inverse pairs ($H \cdot H = I$, $CX \cdot CX = I$) and combine rotation angles ($R_z(\alpha) \cdot R_z(\beta) = R_z(\alpha + \beta)$).

// Quick check if two multi-qubit Pauli operators commute
pub fn commutes(g1: &PauliGate, g2: &PauliGate) -> bool {
    let mut anticommuting_pairs = 0;
    for (p1, p2) in g1.qubits.iter().zip(g2.qubits.iter()) {
        if p1.anticommutes_with(p2) {
            anticommuting_pairs += 1;
        }
    }
    anticommuting_pairs % 2 == 0
}

2. Unitary Verification

To make sure cleaning up the circuit didn't alter its behavior, we compute the full unitary matrix $U \in \mathbb{C}^{2^N \times 2^N}$ and check quantum process fidelity:

$$F(U_{\text{orig}}, U_{\text{clean}}) = \frac{1}{d^2} \left| \text{Tr}(U_{\text{orig}}^\dagger U_{\text{clean}}) \right|^2$$

where $d = 2^N$. $F = 1.00000000$ confirms the physical transformation is identical.

We also built a small C-ABI plugin for Rizin and Cutter (librz_qir.so) so we can open .bc bitcode files and inspect the cleaned circuits directly in the disassembler.

Tracking crypto invariants with eBPF

Auditing crypto calls from user space using LD_PRELOAD doesn't work for statically linked Go or Rust binaries, or when applications call syscalls like SYS_keyctl or AF_ALG directly.

Using eBPF lets you attach probes to kernel crypto functions without modifying the target applications or slowing down the system.

1. Checking for Nonce/IV Reuse

In ciphers like AES-GCM, reusing an initialization vector (IV) under the same key completely breaks authentication and lets an attacker recover the hash key.

With eBPF, we can record seen (key, nonce) pairs in a BPF hash map and emit an alert if a duplicate is observed:

// SPDX-License-Identifier: GPL-2.0
#include <vmlinux.h>
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_tracing.h>

struct crypto_event_t {
    __u32 pid;
    __u32 uid;
    char comm[16];
    char cipher_name[32];
};

struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 65536);
    __type(key, __u64);
    __type(value, __u32);
} iv_map SEC(".maps");

struct {
    __uint(type, BPF_MAP_TYPE_RINGBUF);
    __uint(max_entries, 256 * 1024);
} ringbuf SEC(".maps");

SEC("kprobe/crypto_alloc_skcipher")
int BPF_KPROBE(trace_crypto_alloc_skcipher, const char *alg_name) {
    char name[32] = {};
    bpf_probe_read_kernel_str(name, sizeof(name), alg_name);

    // Flag unauthenticated or obsolete modes (e.g., ECB, DES)
    if (name[0] == 'e' && name[1] == 'c' && name[2] == 'b') {
        struct crypto_event_t *event = bpf_ringbuf_reserve(&ringbuf, sizeof(*event), 0);
        if (!event) return 0;

        event->pid = bpf_get_current_pid_tgid() >> 32;
        event->uid = bpf_get_current_uid_gid();
        bpf_get_current_comm(&event->comm, sizeof(event->comm));
        bpf_probe_read_kernel_str(event->cipher_name, sizeof(event->cipher_name), name);

        bpf_ringbuf_submit(event, 0);
    }
    return 0;
}

2. Low Overhead with Ring Buffers

Events are written to user space via BPF ring buffers (BPF_MAP_TYPE_RINGBUF). Because it's a lockless, memory-mapped circular buffer shared across CPUs, it handles bursts without drops or adding latency to encryption throughput.
